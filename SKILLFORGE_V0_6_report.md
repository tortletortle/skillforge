# SKILLFORGE V0.6 — Active Discriminative Verification

## Status and scope

Implemented in the V0.5.2 source tree; older repair pathways remain unchanged. V0.6 exposes an opt-in Python API `autonomous_repair_v06` and a bounded benchmark CLI script. The experiments are deterministic executable Skill IR/DSL stress tests, not external benchmarks, paid model trials, or real LLM-agent experiments. No API credentials were used. The project remains research-stage. Source-grounded related work: Xin & Reiss, *Identifying Test-Suite-Overfitted Patches through Test Case Generation*, ISSTA 2017 (DiffTGen, DOI 10.1145/3092703.3092718); Yang et al., *Better Test Cases for Better Automated Program Repair*, FSE 2017 (Opad, DOI 10.1145/3106237.3106274); Query-by-Committee/vote entropy (https://scikit-activeml.github.io/development/generated/api/skactiveml.pool.QueryByCommittee.html). These techniques are prior art; no novelty claim is established.

## Implementation

- `prepare`: at most five full patch validations; existing compiler, public tests, contracts and full history are gates. Behaviorally identical serialized executable bodies are deduplicated. A finite shortlist is not a complete hypothesis set.
- `make_pool`: generates up to 96 novel inputs from public examples, input types, and candidate literals. No expected answers are generated by candidate voting. Current implementation mutates one input field at a time; branch coverage is incomplete.
- `verify`: predicts output (or execution failure) on each bounded probe, groups equal outputs, selects maximum vote entropy (uniform prior over structurally different candidates). `active` breaks entropy ties with count of executable candidates, then minimal input-value character size. 480 local candidate-probe executions maximum; reference queries have separate budget. Random and entropy-only baselines share the same pool and shortlist. A `first` comparator performs no oracle or local probe executions; it sees the same prevalidated shortlist, so counted candidate checks reflect common preparation rather than its optimal early-stopping cost.
- `minimum_suite`: for <=5 candidates, exact bitmask set cover of all distinguishable pairs over the available finite pool. Minimize number of probes then sum of input sizes; separately report uncovered pairs. The `min_suite` policy selects a high-entropy query from the optimal suite and recomputes. This is neither global program equivalence checking nor an optimal adaptive decision tree.
- `min_refutations=2`: retain partially refuted candidates for query selection. Release only a unique candidate consistent with every valid response, with each other shortlisted candidate contradicted by at least two distinct probes and at least two valid responses. If there is no oracle, no viable candidate, missing/insufficient evidence or non-discriminable alternatives, abstain. The production wrapper defaults to 4 queries and this strict rule. A single eligible candidate still needs two valid oracle responses; it is not proof that the candidate set is complete.
- `autonomous_repair_v06`: requires external caller-provided oracle (function receiving input only and returning expected output dict or None). Validates the observed body against immutable active version; persists oracle-labeled examples plus observed tests in patch operations; publishes through version store under existing checks and supports rollback. No automatic remote model or oracle service; provenance and authorization of callback are caller responsibilities. No source reliability is inferred from candidate agreement.

## Conditional guarantee

Let d(p) count distinct probes where candidate p disagrees with a supplied label. If the true deterministic program is in the shortlist, all but at most one of the labels are correct, and all executions/labels are assessed consistently, its d(p*) is at most 1. Releasing q requires d(q)=0 and d(p)>=2 for every other candidate. If q differs from p*, the latter criterion is impossible for p*. Therefore a wrong candidate cannot be released under these assumptions. This is a conditional logical property, not a statistical guarantee; it sacrifices availability, cannot recover from all label errors, and fails if the correct program is absent, or more than one answer is wrong. Distinct probes are not necessarily independent sources.

## Experiment protocol and provenance

`exploratory_results.json`: 156 worlds, 13,104 policy-regime-budget evaluations, seeds 62032/77190/94308, four instances per seed/template. 96 worlds: actual planner ambiguity (Tab/newline/NBSP/vertical-tab); 48: controlled two-field 4-hypothesis frontier (manually supplied typed patches, not planner performance); 12: missing true patch (additional tilde replacement outside query pool). Hidden tests use independent PRNG input generation and are scored only after selection; reference answers computed by separate spec functions on requested inputs, never from hidden test file. Pairs share observed/public/history and candidate pool and random ordering. Labels: trusted; unavailable; first answer from alternative world. Budgets 0/1/2/3. This exploratory snapshot predates the redundancy addition and is retained as recorded evidence. The full expanded final matrix timed out; no results from that unsuccessful attempt are used.

`final_results.json`: independent new seeds 62033/77191/94309, one instance per seed/template; 39 worlds (24 planner, 12 controlled dual, 3 absent patch) and 2,808 evaluations, 8 methods x 3 source conditions x 3 budgets (1,2,4). Same template families, no training; deliberately balanced stress populations rather than independent samples from real-world tasks. All methods share per-case candidate pool and the same limits. No test-family novelty, statistical significance or general population rate is claimed. The benchmark generator and raw rows are included. Candidate geometry, input query length, reference-call count and local simulation count are reported separately; these do not measure tokens or actual financial cost.

## Main exploratory results at query budget 2

| Method | Planner correct / 96 | Planner false accept | Dual correct / 48 | Dual false accept |
|---|---:|---:|---:|---:|
| First pass | 48 | 48 | 12 | 36 |
| Random strict | 74 | 0 | 4 | 0 |
| Entropy strict | 96 | 0 | 48 | 0 |
| Active strict | 96 | 0 | 48 | 0 |
| Exact finite-pool suite | 96 | 0 | 48 | 0 |

Active planner: 96 oracle calls, 96 input-value chars vs entropy 288 chars; dual: 96 calls, 576 chars vs 768. Both active and entropy performed 7,140 (planner) + 18,432 (dual) local candidate-probe executions, excluding shared prep. Shorter queries do not establish lower latency/cost or better accuracy than entropy. Exact suite gave no success improvement. In 12 missing-patch worlds, active and entropy both incorrectly accepted all 12 even with trusted labels; the tilde behavior was outside generated probes. No-oracle strict strategies refused all worlds. Under first-answer corruption, basic active accepted all 96 planner and 48 dual worlds incorrectly; two total labels refused all planner worlds but did not prevent any of the 48 dual errors.

## Final confirmation: redundancy experiment at query budget 4

| Method | Trusted correct (36 known-frontier worlds) | Corrupt false accept (36) | Trusted reference calls (36) | Unknown-patch false accept (3) |
|---|---:|---:|---:|---:|
| Basic active | 36/36 | 36/36 | 48 | 3/3 |
| Two total labels | 36/36 | 12/36 | 72 | 3/3 |
| Two refutations per rival | 36/36 | 0/36 | 96 | 3/3 |

At budget 2, strict redundancy solved the 24 planner worlds but refused all 12 dual worlds, even with trusted labels. At budget 4, redundant strategy used 2 oracle calls per planner task and 4 per dual task; all 36 were accepted correctly with trusted source; all 36 were refused under one corrupted first answer. All 39 unavailable-label worlds refused. The three missing-patch cases still falsely accepted: evidence redundancy does not solve open-world incompleteness. The source-error experiment injects one deterministic wrong answer, not real-world noise. Multiple correlated errors remain unresolved. No actual cross-model transfer or lifelong improvement has been measured.

## Reproduce

From project root (Python 3.10+ and NumPy, Python 3.10 uses optional tomli for full TOML parsing):

```
python -m unittest discover -s tests -v
python -m experiments.active_verification.benchmark --out adv_reproduction.json --n 1 --seeds 62033 77191 94309 --budgets 1 2 4
```

Do not run `--n 4` with all methods before checking runtime; the full expanded run timed out in this environment. The recorded exploratory run uses an earlier code snapshot and should not be confused with the final rerun.

## Next decision

Do not add more ranking weights. Prioritize open-world repair (candidate expansion on independent counterexample, typed joint mutations, abstention conditioned on evidence coverage), then use real externally verified tasks with provider credentials and a genuinely independent validator. Use actual token/cost/latency logs in addition to safe acceptance and coverage. Do not claim contest readiness from the synthetic stress population.
